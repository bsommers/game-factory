# collision3d spec (v3)

Reference: `templates/web-project/src/lib/collision3d.js`. Vectors: `spec/v3/vectors/collision3d.json` (`node spec/v3/gen-vectors.mjs [--check]`). Tolerance: abs 1e-9 on all floating values; `null` vs non-null and integer indices exact.

Conventions: right-handed, **Y up**. Vectors `[x,y,z]`, Float64. Triangle soup = flat array, 9 numbers per triangle, CCW front face. Ray = `o + t*d` (d need not be unit, `t` is in units of d). Contact `{normal, depth}`: unit normal; translating shape A by `normal*depth` separates A from B (normal points B toward A). Touching (depth 0) is not a contact. `EPS = 1e-12`.

Functions (vector `op` names in bold): **sphereSphere**, spherePlane, capsulePlane, aabbPlane, **sphereAABB** (centre inside box leaves through nearest face, ties x,y,z), sphereOBB, **aabbAABB** (min-overlap axis), **obbOBB** (15-axis SAT; vector reports `|normal|`), sphereCapsule, **capsuleCapsule**, **sphereTriangle**, **capsuleTriangle** (segment crossing the plane inside the triangle gives depth `r + min(|da|,|db|)` along the face normal), aabbTriangle (13-axis SAT).
Closest points: `closestPointSegment/AABB/OBB/Plane/Sphere`, **closestPointTriangle** (Ericson 5.1.5; zero-area triangles fall back to the nearest edge), **closestSegSeg** (Ericson 5.1.9, returns s,t,d2), closestSegTri.
Rays (return `{t, point, normal}` or null; origin inside a solid shape returns t=0, normal = -normalize(d)): **raySphere**, **rayAABB**, rayOBB, **rayCapsule**, rayPlane, **rayTriangle** (Moller-Trumbore, edges/vertices inclusive within 1e-12 barycentric, parallel or zero-area never hit, `cullBack`, returns u,v,front).
Sweeps: **sweepSphere**(c, r, d, world), sweepCapsule(a, b, r, d, world): `d` is the full displacement, hit `t` in [0,1], `normal` unit from surface toward the shape, `index` the triangle, `face` its oriented face normal, `penetrating` true with t=0 when already overlapping and moving into the surface. Sphere sweep is analytic (face + edge/vertex via ray-vs-capsule); capsule sweep uses conservative advancement (<=48 iterations, contact gap 1e-9). Lowest t wins, ties to the lower triangle index. `world` = flat soup or `{tris, count, candidates(min,max)}` (see bvh `asWorld`).

## Character controller
`createCharacter({pos (feet), radius .4, height 1.8, stepHeight .35, minGroundY cos50deg, skin 1e-4, snapDistance .3, maxIterations 4})`; `moveAndSlide(ch, vel, dt, world)`: depenetrate; horizontal slide (up to maxIterations, planes accumulate, crease = cross product, steep faces project horizontally); step-up when grounded and blocked by a wall (raise up to stepHeight, move, sweep down, accept only walkable faces, adopt only if further than the plain slide); vertical slide; ground snap within `snapDistance` when previously grounded and not rising. Surfaces are classified by the triangle FACE normal (`face.y >= minGroundY` walkable). Output: `pos, vel (actual), grounded, groundNormal, groundIndex, groundMaterial` (see Ground info and moving ground below). The caller owns gravity/jump (supply vel.y). Fully deterministic.

## Character vectors (`spec/v3/vectors/character.json`)
Case: `{name, cfg, world, script, expected}`. `cfg` = `createCharacter` options (`pos` plus any overrides; defaults above). `world` = flat triangle soup. Run with `dt = 1/60` (f64 division), `vy` starts at 0, one `moveAndSlide` per step. Script segments, in order:
- `{vel:[x,y,z], n}`: `n` steps with that constant velocity.
- `{jump:v, n}`: sets `vy = v` first, then falls like below.
- `{dx?, dz?, n}` (gravity mode): each step `vy = (grounded && vy <= 0) ? 0 : vy - 20*dt`, call with `vel=[dx||0, vy, dz||0]`, then after the call `if (grounded && vy <= 0) vy = 0`. (`jump` segments use this mode, and `vy` carries across segments.)
`expected = {trace, final}`: `trace` = one `[x, y, z, grounded(0|1)]` per step (after the call); `final` = `{pos, vel, grounded, groundNormal}`. Compare floats at 1e-9 abs, `grounded` exactly. Reference: `runCharacter` in `spec/v3/gen-vectors.mjs`. Because the controller depends on `sweepCapsule` and `capsuleContacts`, these vectors also cover them indirectly.

## Ground info and moving ground (additive; defaults keep every older vector valid)
- **World materials.** A world may be `{tris, materials?, count?, candidates?}`; `materials` is a parallel array (one entry per triangle, integer id or `null`). A flat soup has no materials. Ports: Rust `World.materials: Option<&[Option<i64>]>`, Go `TriWorld.Materials []*int`, Python/JS `world["materials"]`.
- **Ground info.** After `moveAndSlide`, `ch.groundIndex` is the index of the walkable triangle the character stands on (from the vertical slide hit, else the ground-snap hit; `-1` when not grounded), and `ch.groundMaterial` is `materials[groundIndex]` or `null` (no materials array, `null` entry, out of range, or airborne). Lets `env.surface` (ice, conveyor, river) be keyed by triangle instead of position. Ties follow the sweep rule (lowest `t`, then the lower triangle index).
- **Ground velocity.** `ch.groundVelocity` `[x,y,z]` (default `[0,0,0]`) is an input hint, set by the caller each step to the velocity of the ground the character stood on. It is used only when the character was grounded at the start of the call. The `world` passed in is the platform at its CURRENT (already moved) position. Order inside the call: depenetrate (a platform that rose into the capsule pushes the character up), then carry: horizontal slide by `gv.xz*dt`, then, if `gv.y > 0`, an upward sweep by `gv.y*dt` (stops at ceilings), then the normal `vel` slide. The ground snap condition becomes `vel.y - gv.y <= 0` (the character is not leaving the platform if its upward speed does not exceed the platform's), so a platform rising faster than the character never leaves it floating or penetrated. Output `vel` stays the actual displacement/dt (includes carry). With `groundVelocity = 0` behaviour is identical to before.
- **Vector additions** (`character.json`, 10 new cases): case flag `reportGround: true` adds `final.groundIndex` and `final.groundMaterial` (ints exact, `null` exact) to the comparison. `world` may be `{tris, materials}`. A script segment may carry `platform: {from, count, velocity}`: before each step of that segment triangles `[from, from+count)` of a private copy of the world are translated by `velocity*dt` (per component `tris[i] += velocity[i%3]*dt`) and `ch.groundVelocity = velocity`; segments without `platform` set `groundVelocity = [0,0,0]`. Trace/other fields are unchanged.
