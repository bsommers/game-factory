# vfx3d: data-driven river / sewage / whirlpool / fire effects

One JSON definition drives BOTH gameplay and visuals. Pure deterministic JS reference: `templates/web-project/src/lib/vfx3d.js` (zero deps, Y-up, metres, seconds, no `Date`/`Math.random`; particles use a seeded mulberry32 per particle id). Godot visuals: `templates/godot-action3d/vfx/` + `scripts/vfx/vfx_loader.gd`. Schema: `spec/v4/schemas/vfx3d.schema.json`; examples: `spec/v4/examples/vfx3d/{whirlpool,flood-water,toxic-sludge,fire,steam-vent,hit-spark}.json` (copied byte-for-byte to `templates/godot-action3d/vfx/defs/`; a test enforces equality).

## Definition
`{id, kind: whirlpool|water|sludge|fire|steam|spark, seed, field?, water?, visual?, emitters?[]}`. Required blocks per kind: whirlpool `field(vortex)+visual`; water/sludge `water`; fire/steam/spark `emitters`.

- `field` is the gameplay force and is shared data. `vortex` is key-for-key the boss3d vortex hazard (`center, radius, strength, falloff, swirl, ramp, coreRadius, coreDps, pulse{period,active,telegraph,idle}, resistFactor`) and `fieldForce` is the same formula as `boss3d.vortexForce` (inward `strength*amp*(1-d/R)^falloff` plus tangential `swirl`; `amp` = ramp * pulse). `flow` is `{flow:[x,y,z] m/s, area?, dps?, ramp?, pulse?}` for rivers, sludge drift, steam updrafts and fire damage zones (feed locomotion3d `env.surface().flow` / `env.force`). `area`: `{shape:'cylinder', center, radius, height?}` (height is up from center.y) or `{shape:'box', center, size}`.
- `water`: `{level, size:[w,d], rise?{fromY,toY,seconds}, waves[1..4]{dir:[x,z], wavelength, amplitude, steepness 0..1, speed?, phase?}}`. Gerstner waves (GPU Gems ch.1): rest-grid point p0 moves to `p0 + sum qa_i d_i cos(th_i)` horizontally and `sum a_i sin(th_i)` vertically, `th = k d.p0 - omega t + phase`, `k = 2pi/wavelength`, `omega = k*speed` (speed defaults to deep-water `sqrt(g/k)`), `qa = steepness/(k n)`. `waterHeight(water,x,z,t)` inverts the horizontal displacement by 4 fixed-point passes so gameplay height at a world (x,z) agrees with the vertex shader. `water.rise` is the boss3d flood hazard level (linear).
- `visual` (renderer only): colours (`#rgb`/`#rrggbb`/`[r,g,b]`), `foam 0..1`, `opacity`, whirlpool `swirlRate` (rad/s), `twist`, `arms`, `depth` (funnel depth m), `funnelPower`. Funnel profile `depth*(1-r/R)^funnelPower*amp` is `funnelDepth` in JS and the whirlpool shader (R = `field.radius`), so `surfaceHeight` (a floating body's height) equals the drawn surface.
- `emitters[]`: `{id, rate | burst{count<=999,time,repeat}, duration, lifetime n|[a,b], maxParticles<=5000, shape{type point|sphere|box|disc|cone, radius, size}, direction, spread (deg), speed n|[a,b], gravity, drag, size{start,end}, color[{t,c,a}], blend add|mix}`. `emitterParticles(em, seed, t)` is closed-form and stateless in `t` (linear drag), so the same seed and time always give the same particles. Validation rejects more than 5000 live particles.

## Godot
`vfx_loader.gd`: `build(def, {time, preprocess}) -> Node3D` (water plane with `water_gerstner.gdshader`, radial funnel mesh with `whirlpool.gdshader`, one `GPUParticles3D` per emitter with `ParticleProcessMaterial` + radial-gradient billboard quads), plus GDScript twins of `field_force`, `gerstner`, `water_height`, `water_level`, `funnel_depth`, `field_amp` (parity-tested against the JS numbers). `vfx_instance.gd` drives shader time and field amplitude (`fixed_time >= 0` pins time for screenshots). Everything works on the Compatibility (opengl3 / llvmpipe) renderer: no screen/depth textures. GPU particles are not bit-identical to the JS evaluator (damping approximates drag, a burst repeats every max(lifetime, repeat)); fields, water height and funnel are exact. Previews: `vfx/scenes/preview_*.tscn`; screenshots in `docs/screens/vfx/` via `godot.shot`. Tests: `godot.test {runner: "res://tests/run_vfx.gd"}`.

## Capabilities
`vfx3d.validate {effect|file}` (errors with JSON paths, warnings), `vfx3d.sample {effect|file, what: field|water|surface|particles, points, times, resisting, emitter, limit}`.
